# Profile 与订阅统一设计（草案 v0.3）

2026-09-13 修订。依据工作树 `2eab57f` 的界面代码、[产品设计](../../DESIGN.md)、
[架构](../../ARCHITECTURE.md) 与事故记录整理；本稿是待实现设计，不代表已完成的兼容能力或现场验收。

实施状态和本版兼容边界见 [XDial Next](../agent/profile-next.md)；以下保留目标设计，未实现项不能作为当前能力。

**Profile 管理一整套网络配置；订阅负责取得和更新配置；Scenario 决定怎样使用配置。**
保留现有线路、规则、场景的交互，替换旧 Subscription 领域模型。

## 1. 配置模型

```text
Profile（本地新建 / 文件导入 / 链接订阅）
├─ 共享资源：线路、线路组、规则集、DNS 服务
├─ 场景：名称、图标、SSID、有序分流规则、默认出口及配套 DNS 策略
└─ XDial 元数据：格式版本、来源、对象身份、凭据引用
```

- 可保存多个独立 Profile；资源在同一 Profile 的场景之间共享，不隐式跨 Profile 引用。
- 线路使用 sing-box 的 `outbounds` / `endpoints`，规则集使用 `route.rule_set`；场景中的分流使用原生 `route.rules` / `route.final`。来源与场景扩展放入 `xdial` 命名空间。
- 共享规则集只存匹配条件。根级不另存一套用户分流规则；场景是用户流量的唯一绑定点，DNS 与路由从同一场景编译、共同生效。
- 展开场景所需依赖、注入凭据与平台事实后，形成一份运行配置。复用原生解析、校验与执行，不另造匹配引擎。结构参照 [sing-box 配置](https://sing-box.sagernet.org/configuration/) 与[路由规则](https://sing-box.sagernet.org/configuration/route/rule/)。
- 编辑中的 Profile、用户连接意图、实际运行快照分别保存。运行身份包含 Profile ID、Scenario ID 和有效配置版本；凭据、协议身份状态和缓存按 Profile 隔离，避免同名对象串用。
- 语言、外观、软件更新和登录启动属于应用设置；设备认证状态与密码属于本机安全存储。企业版使用同一正式 App 和更新通道，只分发外部 Profile。

## 2. 保留现有 UI，增加 Profile 上下文

功能树、菜单和界面导航保持同一层级，常规菜单不超过三层。设置窗口的“配置”和“通用”
是同级、互斥的两个区域。配置入口包含当前 Profile 与下拉箭头，选择和管理 Profile；
当前 Profile 的线路、规则、场景为第二级。具体对象在页面内编辑，不另设 Profile 管理页。

```text
配置 · 公司配置 ▾           通用
线路   规则   场景                         更新于…
------------------------------------------------------
                   当前页的既有卡片
```

| 表面 | 本次设计 |
|---|---|
| 配置／通用（第一级） | 两个区域互斥选中。点“通用”展示应用设置；点“配置”恢复上次的 Profile、页签与展开项，箭头单独打开配置菜单 |
| Profile 下拉菜单 | 按“切换配置 → 当前配置 → 添加配置”排列；用分组标签和分隔线表达归属，不增加子菜单 |
| 线路页 | 保留协议表单与折叠卡片，增加独立线路组卡片；移除旧订阅大卡片。来源只作辅助标记，不成为出口类型 |
| 规则页 | 保留手动域名/CIDR、应用与进程、URL 规则、反向、获取线路和外部规则预设；转换为原生表达，应用身份采集仍由平台负责 |
| 场景页 | 保留名称、图标、SSID 胶囊、模板、有序“规则 → 出口”和默认出口；出口只选择线路或线路组 |
| Popover | 仅作为使用入口，保留 Profile 选择、场景圆球、连接状态、进度、速率、出口地址和详情；不承载 Profile 管理或配置编辑。设置窗口的菜单层级不套用到此处 |
| 交互细节 | 保留折叠、行内控件独立点击、顶层长按排序、绑定行专用拖动把手、成功落下保存一次、键盘和 VoiceOver 操作 |

通用页不显示 Profile 名称、配置子菜单、订阅更新时间、待应用提示或添加资源按钮。
Profile 的选中项与通用区域状态分别保存；返回配置无需重新选择 Profile。不同 Profile
分别记住上次的页签，各页签记住展开项。通用按启动与连接、界面、安装与更新组织，修改
通用偏好不改变当前 Profile，也不触发网络配置待应用。

配置下拉菜单的固定分组与顺序：

1. **切换配置**：列出全部 Profile，勾表示正在编辑的配置，不代表正在连接。
2. **当前配置 · 名称**：重命名；订阅设置、立即更新（仅订阅配置）；创建本地副本；导出；
   删除。操作均作用于明确显示的当前 Profile，删除置于该组末尾。
3. **添加配置**：新建空白配置、从文件导入、从链接订阅。三者均创建新的 Profile。

重命名不再藏在“配置与订阅设置”中，本地 Profile 不显示订阅操作；复制虽产生新对象，
其来源是当前 Profile，因此归入当前配置操作。取消编辑或创建回到原页，保持导航上下文。

切换浏览或编辑的 Profile 不连接、不重连。Popover 中点击场景圆球才发起连接或切换；浏览其他 Profile 时，
Popover 仍明确显示实际正在使用的“Profile · 场景”，不能把浏览选择画成连接成功。
SSID 自动匹配限定在用户已激活的 Profile 内，保持精确匹配、手动选择优先和显式断开后不自动连接。
模板仅引用确实存在的资源，缺少依赖时提示补齐，不生成虚构的线路 ID。删除正在运行的 Profile 前先切换或断开，不由删除操作暗中终止连接。

普通表单继续编辑常用字段；能由当前核心执行、但表单无法完整表达的原生内容，提供高级配置查看/编辑。
往返保存必须保留这些内容。核心或平台不支持的语义需明确报错，不能把字段删掉后声称导入成功。
iOS / tvOS 复用同一模型与导入结果，保留各平台布局；移动端当前连接期间的编辑限制单独按平台验收。

## 3. 新建与机场兼容

流程为“新建 Profile → 填链接或选文件 → 自动识别并预览 → 保存 → 点击场景使用”。
手动新建从 Direct 与默认场景开始。导入只保存配置，不自动连接、测速或启动声明中的 VPN。

| 来源内容 | 初始结果 |
|---|---|
| XDial 完整配置 | 保留共享资源和已有场景；没有场景时补默认场景 |
| sing-box 完整配置 | 提取共享资源，将原有路由与配套 DNS 策略转为默认场景；检查平台接入约束 |
| Clash / Mihomo、Surge | 转换支持的线路、线路组、规则及外部资源引用，保留顺序和默认行为，创建默认场景 |
| Base64 / 节点 URI 列表 / 仅节点集合 | 导入线路并创建原生选择组，默认场景指向该组；规则区可以为空 |

默认自动识别，手动指定格式放在高级项。机场可能只提供代理集合，规则集合需另行获取，
不能把所有订阅当成完整分流配置，参照 [Mihomo 代理集合](https://wiki.metacubex.one/config/proxy-providers/)。

“尽量支持”落实为持续扩展的导入适配器与协议能力表：优先原生 XDial / sing-box，再覆盖现有
Clash / Surge / URI 入口及机场常见 provider 引用。转换在本机完成，不依赖公共订阅转换服务。
预览报告可用线路、规则、场景和具体不兼容项；影响行为的缺失阻止作为完整配置启用，
也可由用户明确选择“仅导入可用线路”。不能静默跳过路由、把 fallback 改成 urltest 或回落 Direct。
当前构建注册的是 sing-box 的部分协议；格式可识别与当前平台可执行分别判断。

## 4. 更新与本地修改

- 每份 Profile 保存订阅基线与本地新增内容。订阅内容标记来源；编辑源场景时先复制成自己的场景，避免第一版引入复杂的逐字段冲突合并。
- 来源通过 Profile 管理。普通订阅 Profile 使用一个完整配置来源；多个既有订阅的刷新关系可作为内部来源记录迁移，不恢复旧 Subscription 出口。
- 资源身份与显示名称分离，刷新沿用身份及用户的有效节点选择；不得每次解析重新生成全部 ID。来源无稳定 ID 时保存匹配关系，重名、改名歧义需报告。
- 下载、解析、凭据入库、引用校验全部成功后才原子接受新版本。本地新增场景及其顺序保留；源对象删除造成引用失效时，保留上一份有效版本并显示冲突，不能静默改绑。
- 手动/定时刷新只更新已保存内容。影响当前运行场景时，沿用“修改已保存，当前连接尚未应用”；用户点击“应用并重连”才启动切换。无关对象、改名、图标及更新时间不触发待应用。
- URL token、节点密码和个人凭据进入 Keychain；凭据引用置于 XDial 扩展，编译时注入原生字段。原始订阅响应、缓存和导出也要处理凭据，不能只清理最终 Profile。Keychain 不可用时不得当成空密码覆盖旧值。
- 原生 Profile 导出保留本地自建内容，默认去除秘密与带 token 的来源地址；单场景可导出标准 sing-box 配置，缺少凭据时明确标明需要填写。配置格式版本、订阅内容修订与 App 版本分别管理。

## 5. 迁移与旧代码删除

旧模型可删除，用户数据通过一次迁移保留。当前单份配置整体成为“我的配置”，保留现有场景、
名称、图标、SSID、排序、默认出口、线路与登录身份，不强行拆成互不关联的 Profile。
旧订阅节点与策略组进入共享资源；订阅 URL 进入来源记录。

特别处理旧 `RuleBinding.subscription_id` / `default_subscription_id`：它们可能嵌套订阅内部路由。
迁移须把外层匹配范围、内部规则顺序、未命中行为和 DNS 归属一起展开为场景原生表达，
不能仅将“订阅”替换成 selector。旧订阅刷新时也要重新生成其拥有的表达，并与本地场景共同校验。

迁移成功并验证前保留原配置，原有秘密材料按安全迁移处理，不额外制造明文备份；
Keychain 写入与读回成功后才清理旧明文 vault。无损转换失败时保留旧数据并明确报告，不以部分数据覆盖。
旧格式只留导入迁移入口。最终移除旧 Subscription 模型、专属 UI、第二套规则表达与生成分支；
已有解析能力和回归样例经审核复用。AnyConnect 的 sslcon 替换以认证、重连、企业 DNS 和切换验收为前提。

## 6. 必须保住的回归行为与实施顺序

| 依据或风险 | 验收行为 |
|---|---|
| 当前有序规则及 [DNS 事故](../incidents/d35-transparent-proxy-evidence.md) | mixed/IP 规则在前时不吞掉后续域名 DNS 规则；Direct、企业 DNS、MagicDNS 与出口归属一致 |
| 现有编辑与待应用机制 | 查看、展开、排序展示项、刷新无关对象不改变运行；修改有效分流才提示待应用 |
| 当前 Popover 的切换点击分支 | A 运行、B 准备时，点击 A 改为取消 B 并保留 A；再次点击 B 也只取消候选。无候选时点击运行场景仍断开，徽标随动作一致 |
| 快速切换与跨 Profile 切换 | A→B→C 仅最新意图可提交；旧请求迟到不能覆盖新 Profile。候选准备、失败或取消期间旧连接继续工作 |
| 订阅刷新与持久化 | 改名、重排、节点删除、重复刷新、离线重启及中途退出不串引用、不抹掉本地场景或凭据 |
| 平台与 UI | 保留 SSID 权限及自动匹配、卡片拖动、长名称与错误展示、Debug/正式数据隔离；声明的资源不全部启动 |

当前 `MainPopover.performScenarioAction` 在 B 准备时点击运行中的 A 仍调用 `disconnect()`；
本稿将其列为需要改变的交互。历史调查仅提供回归线索，本轮没有复现现场断网或认定所有旧问题仍存在。

实施按三步推进：① 原生模型、迁移与持久化；② Profile 管理、导入刷新与现有界面接入；
③ 删除旧路径、补齐兼容适配和真实网络验收。新功能依赖的最低兼容能力在第二步可用，
旧路径只在迁移前后代表性场景的线路、规则顺序、DNS 和真实流量等价后删除。
UI 改动前基于本稿提供布局预览；此稿本身不修改运行逻辑、用户配置或安装中的 App。
