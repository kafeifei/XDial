# XDial Next 界面重设计 · 结构与交互草案

后续实施范围已按用户调整：保留现有配置 UI；仅将“通用”改为下述独立分类设置窗口，
Profile 保留选择与管理、移除“通用 / 配置”页面切换职责。本文其余整体重设计暂不实施。

依据 `d2aff0296b` 的领域模型、控制面、产品功能及用户本轮要求整理。本文取代旧草案中的
“保留现有 UI”方向；本轮只产出设计和交互原型，不改运行中的 App 或网络。

## 1. 先明确软件是什么

XDial 管理一份网络配置如何被某个场景使用。它有三个独立层面：

| 层面 | 对象及职责 | 用户动作 |
|---|---|---|
| 配置 | Profile 包含共享线路、线路组、规则集以及多个场景 | 建立、导入、编辑、订阅更新、导出 |
| 使用 | 当前连接持有一个 Profile 的一个场景及已提交快照 | 连接、切换、取消、断开、重试、应用已保存的修改 |
| 应用 | 启动偏好、外观语言、系统组件、权限、更新和卸载 | 管理这台 Mac 上的 XDial Next |

场景引用线路和规则，不拥有另一套线路和规则。规则集只有匹配条件；有序匹配与出口绑定、
默认出口属于场景。线路组仍是一种线路，订阅则是整个 Profile 的来源。
DNS 解析与分流从同一个场景编译，由 sing-box 裁决，不在界面中另外构造一套 DNS 路由逻辑。
Tailscale 登录身份由同一 Profile 共享，线路选择出口节点；不同 Profile 的身份独立。

业务所有权是引用图；**功能组织和菜单导航是树**。查看“被哪个场景引用”属于跳转，
不会把一个规则在多个场景下复制成多份编辑入口。

## 2. 功能树就是菜单树

```text
配置窗口
└─ 当前 Profile ▾                         一级：窗口标题中的低频下拉
   ├─ 场景                               二级：同级功能
   │  └─ 某个场景                        三级：列表选中后右侧编辑
   ├─ 线路
   │  └─ 某条线路 / 某个线路组
   └─ 规则
      └─ 某个规则集

应用设置（独立小窗口，不属于任何 Profile）
├─ 启动与连接
├─ 外观与语言
├─ 系统与权限
└─ 关于与更新

菜单栏（使用入口，不是配置入口）
├─ 当前连接及操作
├─ 当前配置的场景列表
└─ 连接详情、打开配置；低频切换 Profile 收在详情中
```

场景、线路、规则按“使用组合 → 提供出口 → 提供匹配”排列；打开配置默认进入场景。
每个 Profile 单独记住上次查看的分类和对象。Profile 数量通常很少、切换不频繁，
因此不用 Profile 侧栏、Profile 首页或常驻配置管理卡片。

Profile 下拉保持平铺：选择 Profile；当前 Profile 的重命名、来源与刷新（仅订阅）、
创建本地副本、脱敏导出、删除；最后是新建、文件/链接导入和从本机 Debug 导入。
这些是对象动作，使用对话框完成，不增加第四层子菜单或 Profile 管理页面。

场景的名称、图标、SSID、分流表和默认出口是对象属性，不做下一层导航。
线路协议表单和规则类型表单也遵循同一原则；高级字段是原位展开，不是新菜单。

## 3. 配置窗口

采用双栏：左侧是分类与对象列表，右侧是单一对象的完整编辑器。窗口标题旁显示当前
Profile 和小下拉；列表底部是“新建”，应用设置入口独立固定在左下角。

对象列表只显示名称、用途摘要、来源和必要的引用状态。编辑控件留在右侧，
不把删除、开关、展开和连接操作挤在同一行。列表选中只表示正在编辑。

### 场景

- 默认展示有序分流表：顺序、匹配规则、使用线路。专用把手拖动；另提供上移/下移操作。
- “其余流量”固定在表尾，选择默认出口，不能拖到普通规则中间。
- 名称和图标就近编辑；Wi-Fi 自动选择放在分流之后，完整列出绑定 SSID。
- 添加规则从同一 Profile 的共享规则中选择，不在场景里再造一个规则编辑器。
- 空场景显示“所有流量使用默认出口”；新场景可从已有资源组成的模板建立。
- 缺失、禁用、互相冲突的依赖在引用位置报错，不静默更换为直连。

### 线路

- 普通线路按协议显示服务器、端口、认证与 TLS 等字段；密码默认遮盖，允许显式查看。
- Direct 为固定资源；展示继承当前系统网络的含义，不提供伪造的“物理网卡/DNS”选择。
- 线路组显示成员、手动选用成员或自动测速设置；不混入 AnyConnect/Tailscale 等
  当前不能被组复用的适配线路，不默认对所有声明线路发起测速。
- Tailscale 显式登录/刷新后显示身份与节点。打开编辑器不登录、不检测、不建立连接。
  Auth Key 为一次输入，用后清空；显示同 Profile 共享身份以及独立于 Debug 的事实。
- 高级原生选项就地展开；表单编辑不能删除未被表单表达的原生字段。
- 详情末尾列出引用它的场景、线路组和规则获取任务；点击引用回到唯一拥有该功能的页面。

### 规则

- 规则类型包括域名/IP、应用/进程、远程规则集及 sing-box 匹配表达。
- “启用”和“反向匹配”是两个独立属性；反向只改变匹配范围，不改变出口。
- 远程规则显示来源 URL、格式和获取线路。“获取线路”属于规则文件下载，
  与用户流量的场景分流分开标注；连接前的获取失败与有效缓存保留都可明确呈现。
- 程序选择保留应用身份与进程名称/路径能力；从运行程序添加为显式采集动作。
- 列出引用场景，删除前检查引用；不留下失效的分流行。

### 编辑、保存和运行

本稿提出统一的**对象草稿 → 保存修改**，替代旧表单各字段即时落盘和少数高级表单手动保存的混用。
页面底部只在有草稿时启用“保存修改/放弃修改”；字段错误就近显示。
跨对象、分类或 Profile 离开时，有未保存修改则选择保存、放弃或继续编辑。
打开独立应用设置窗口不丢弃草稿，关闭后回到原对象和原输入。

保存不连接。对当前运行依赖有影响时，提示“已保存，当前连接仍使用之前的配置”，
进入菜单栏面板后才能明确“应用修改并重连”。修改名称、图标、SSID、视觉顺序或未被使用的
资源不产生待应用标记。待应用必须继续采用 Go 的有效指纹，不以整个文档不相等替代。

## 4. Profile 生命周期与订阅

| 动作 | 界面与结果 |
|---|---|
| 新建空白 | 名称确认后得到 Direct 与一个默认场景，进入其编辑器 |
| 文件/链接/Debug 导入 | 输入来源 → 识别与完整性检查 → 数量、默认场景、未支持项预览 → 保存新 Profile |
| 仅节点订阅 | 显式导入线路，生成选择组和默认场景；规则列表可为空 |
| 完整来源不支持 | 明确列出阻止迁移的语义；允许用户主动改为仅线路，不能自动降级 |
| 订阅资源 | 来源拥有的资源只读；本地新增对象可编辑；selector 的个人选择按现有例外保留 |
| 修改来源内容 | 创建本地 Profile 副本或本地场景副本，再编辑；不把源内容变成难以解释的半覆盖 |
| 更新 | 同一处显示获取/检查/保存阶段；引用失效则保留旧版，列出冲突对象与重试入口 |
| 删除 | 在对话框中列出影响；运行中的 Profile 禁止直接删除；至少保留一份配置 |
| 导出 | 默认去掉密码、密钥和可能带凭据的 URL；明确“接收方需补填”，不能称为完整备份 |

本地 Profile 不显示“订阅更新”。订阅管理收在 Profile 下拉里，不占日常编辑区域。
刷新只更新配置库，不替换当前运行快照。凭据与订阅 URL 存在加密库，显示层不提供关闭加密选项。

## 5. 菜单栏：只服务日常使用

场景采用纵向列表与有文字的动作，去掉圆球式复合操作。顶部始终显示真实正在使用的
“Profile · 场景”，没有连接就显示未连接。Profile 切换在详情内，不是面板的主控件。

| 状态 | 主要表达与动作 |
|---|---|
| 未连接 | 场景行“连接”；无需先选一个场景再找总开关 |
| 已连接 | 当前场景标记“使用中”，顶部有明确“断开”；其他场景行“切换” |
| 首次连接准备中 | 当前目标、真实任务进度、“取消” |
| 场景切换准备中 | 原场景保持使用中，目标显示准备进度；“取消切换”只取消候选 |
| 候选失败 | 指出目标失败和原因，明确“仍在使用原场景”；重试或关闭错误 |
| 断开/回滚/恢复中 | 展示对应动作与结构化进度，不混称为连接中 |
| 配置已保存待应用 | “应用修改并重连”，原场景仍显示使用中 |
| Wi-Fi 权限不足 | 只提示自动选择不可用，手动使用不受影响 |

详情按需展开：实际使用的线路与出口观察、规则归属、准备任务、错误与重试。
诊断数据源是当前事务，不把已配置未使用的线路标为在线。下载速率、上传速率和时长只显示一次。
最新目标优先；迟到回调不得覆盖新的选择。复制、重命名、浏览 Profile 不改变连接。

## 6. 应用设置与其他窗口

应用设置使用独立小窗口，按四组显示，关闭即返回原配置编辑上下文。

| 分组 | 功能 |
|---|---|
| 启动与连接 | 登录启动、启动时自动连接；说明自动恢复与启动偏好不同 |
| 外观与语言 | 跟随系统/浅色/深色；中文/English，保持对象名称原样 |
| 系统与权限 | 后台服务、网络扩展、Wi-Fi 位置权限状态；安装/修复、脱敏诊断、卸载入口 |
| 关于与更新 | 当前版本、构建、Next 通道；更新来源与候选、下载、验证、安装交接 |

安装/修复用独立任务表，等待系统批准与操作失败区分；安装不接管网络。
卸载明确目标为 XDial Next，区分移除组件与删除 Next 数据；不动 Debug 或正式版。
更新窗口展示当前版本、候选与说明、下载/验证/交接状态；下载不重连，安装交接需显式操作。
Next 当前没有正式更新订阅，原型采用“选取 Next 更新包”的目标流程，不能把它说成现有能力。

## 7. 实现范围与需要改动的部分

| 模块 | 当前已有 | 本设计需要实现 |
|---|---|---|
| Profile | 加密库、导入/复制/刷新/导出、编辑/运行身份分离 | 标题菜单、各对象编辑位置恢复、统一草稿离开保护 |
| 场景 | 绑定/默认出口/SSID/图标/模板、候选切换 | 列表与详情编辑器、清晰有序分流表、引用跳转、显式场景动作 |
| 线路 | 9 类出口/适配/组能力及高级选项、Tailscale 设置会话 | 按协议详情、统一校验/保存、引用关系与空状态 |
| 规则 | 手动/应用/远程/原生匹配、反向/启用、获取线路 | 类型详情表单、唯一编辑入口、引用保护提示 |
| 使用面板 | 结构化连接/切换/回滚/恢复与观察事实 | 新场景列表、明确动作、浏览与运行分离呈现 |
| 应用设置 | 启动/外观/语言/安装卸载、正式通道更新器 | 独立窗口和分类、Next 手动选包流程（新增）、诊断导出产品入口（新增） |
| 原生配置能力 | 当前受限的 sing-box 结构及转换器 | 自定义 DNS 完整往返、更多 endpoints/actions/协议和旧嵌套订阅迁移另立能力工作，不以 UI 冒充完成 |

本次原型覆盖所有主要页面、对象草稿与保存、Profile 创建/复制/导入预览、订阅只读/冲突、
引用阻止删除、应用设置、安装更新卸载的模拟流程、菜单栏连接/切换/取消/失败保留旧连接。
所有内容都是示例数据和本地模拟；不读取真实凭据，不写 App 配置，不连接真实网络。

## 8. 验收点

1. Profile 切换低频收纳，默认是场景；每个功能只有一个所属页面，普通路径最多三级。
2. 列表选择与连接选择独立，设置页没有隐式连接动作；应用设置不属于任何 Profile。
3. 编辑器在切页时保护草稿；保存失败不谎报成功，取消新建不留残对象。
4. 分流顺序与默认出口完整保留，删除资源不制造悬空引用。
5. 订阅资源与本地资源、已保存与已应用、未知与已验证、安装成功与连接成功分别表达。
6. 连接失败、取消、权限不足、空配置、长名称、窄窗口和键盘操作都有明确可用状态。
7. Debug 的进程、数据和网络完全不参与原型；正式实现时继续独立交付 Next。

## 9. 本轮原型核验

浏览器内实际操作核验了草稿离开保护、应用设置返回后保留输入、保存后待应用、
模拟候选失败保留旧连接、被引用线路阻止删除、订阅资源只读、链接导入预览与保存、
脱敏导出摘要。检查了 1024、736、320 像素宽度及深色外观，修正窄窗口分流字段的挤压。
浏览器未记录脚本错误；这些只证明原型交互，不代表 App 或协议实现已经完成。

本轮仅新增本设计文档与独立交互草图。结束时只读确认 Debug 进程、连接事务及场景未变化，
外网请求返回 HTTP 204；Next 仍未连接，自动连接关闭。
