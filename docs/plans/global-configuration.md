## 对象归属

Profile 是资源来源与管理边界，只包含线路和规则。手动创建和订阅导入都采用此边界；
不同订阅的资源隔离，引用保留来源与稳定身份，同名对象不自动合并。

线路组和场景属于整个配置库。线路组可以组合多个 Profile 的线路或其他全局组；
场景可以引用多个 Profile 的规则，并绑定到线路或全局组。只有场景决定用户流量的
规则顺序、出口和默认出口。组的固定选择或自动选择设置由引用该组的所有场景共享。

## 首次导入与后续刷新

| 对象 | 首次导入 | 后续刷新 |
|---|---|---|
| 线路、规则 | 导入所属 Profile | 更新来源资源，保留本地独立资源 |
| 场景 | 从源策略创建全局场景 | 保留本地名称、顺序、绑定、默认出口、图标和 SSID |
| 策略组 | 从源组创建全局线路组 | 保留本地名称、选线模式、固定选择与测速设置 |
| 手动组成员 | 引用明确选择的线路或组 | 不自动吸收订阅新增成员 |
| 跟随来源的组成员 | 建立显式来源关系 | 跟随该源组的成员变化，保留另外手动添加的成员 |

源策略组的成员关系属于订阅元数据，不作为 Profile 下第三类用户可编辑对象。
后续刷新发现源新增场景或策略组时，提示可导入，由用户选择，不自动创建全局对象。
“从订阅重新生成”作为明确的用户操作，与普通刷新区分。

源配置只有一个场景时，创建名称采用订阅名称；多个场景采用“订阅名 · 场景名”。
创建后名称归用户维护，订阅重命名或刷新不覆盖它。身份与显示名称分离。

被引用资源删除、固定成员失效、组循环或规则部分引用失效时，刷新必须给出明确原因。
第一版沿用整笔拒绝并保留上次有效配置的行为，不静默换成直连或其他出口。
新增规则内容可随所属规则刷新；新增规则对象和源出口策略不自动改写已有场景绑定。

## 单窗口导航

顶层采用 `[Profile ▾ | 线路 规则] [线路组 场景] [通用]` 三块单行分组，间隔 10 pt，整体按整个标题栏宽度居中。

- Profile 选择、创建、导入和订阅管理放在顶栏左侧资源分组，线路与规则共用所选 Profile；不影响全局页面。
- 线路组和场景始终显示全局对象，跨来源选择器明确显示资源来源。
- 通用嵌入同一配置窗口，保留现有偏好功能，移除单独的通用窗口入口。
- 切页、打开设置、改名和浏览资源不触发网络动作。
- 实施前提供保持现有视觉风格的可检查界面预览。

## 实施与验证

1. 配置库升级：建立全局组、场景和跨来源引用；迁移现有 Profile 内对象及引用，
   保留顺序、固定选择、SSID、活动场景和凭据。旧库保留可恢复副本；旧版本明确拒绝
   不支持的新格式。Tailscale 身份继续保持原来源归属，不因全局组合重新登录或合并身份。
2. 导入刷新：分离资源更新和首次策略生成；校验跨来源依赖，保证失败时整笔不落盘。
   保存源对象与本地对象的稳定映射，避免靠显示名称关联。
3. 运行编译：从所选全局场景收集有效依赖，由 Go 编译完整运行快照、计划和指纹。
   继续复用 sing-box 与现有 Prepare/Commit 事务；保存和刷新不修改已提交连接。
4. 宿主与 UI：设置、Popover、SSID 激活、资源选择器、测速状态统一使用正确的
   全局或来源作用域，通用并入配置窗口。测速和固定选择的既有边界保持一致。
5. 导入导出：Profile 导出仅包含所属资源；加密本地库与升级备份包含全局对象及
   来源关系。资源单独导出遇到外部引用时拒绝，不生成依赖悬空的配置包；本轮不新增便携整库备份界面。

源删除依赖时的原子回退；固定选择和手动成员保留；多 Profile 迁移后路由语义一致；
SSID 全局冲突检测；场景切换失败保留旧事务；五页导航与通用在同一窗口中工作。
